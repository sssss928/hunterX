timed out, failed during collection, or could not run in the host environment
is not counted as a pass. Live ticket ordering, CAPTCHA/queue bypass and
payment were not performed.

## v0.4.8 focused results

- Initial timing regression exposed two naive/aware datetime arithmetic bugs;
  fixed, then 47 timing/gate cases passed.
- Initial soft-block regression exposed a lazy PlatformEngine import error;
  fixed, then 36 soft-block cases passed.
- A combined long command exceeded its tool window; files were rerun separately
  rather than counted as passed.
- A new safety test import exposed import-time replacement/closure of captured
  Windows stdout/stderr. The console setup was changed to interactive-only
  `reconfigure`; the isolated test then passed.
- Version/config tests initially failed because old assertions required no
  `refresh_calibration`. v0.4.8 intentionally makes the aware timezone default
  authoritative; assertions were updated to verify `Asia/Taipei`.
- Latest combined focused gate: 217 passed in 8.12 s; Ruff, compileall and
  strict-mypy for seven new/changed typed core modules passed.

duplicate calibration mapping copy was removed before the final measurement.

ms; same-document no-ticket 1.1798 ms; 100 tab-state intents 3.6880 ms; 1,000
tab-state intents 41.0326 ms; scheduled dispatch 36.2914 ms. These fixtures do
not open 1,000 Chrome tabs; they measure bounded registry/coordinator state.

## Windows build and smoke

- PyInstaller 6.21.0 built `nodriver_tixcraft.exe` and `settings.exe` from the
  maintained spec files.
- The packaged archive verifier passed: CRC OK, 345 entries, zero missing,
  isolated runtime layout, 373,830,820 bytes.
- The archive was extracted into a fresh path containing spaces.
- `settings.exe http /run smoke test` exited 0 and printed
  `smoke test ok: HunterX (0.4.8)` plus notification/config checks.
- `nodriver_tixcraft.exe --help` exited 0 and exposed both `onsale` and
  `leak_watch` mode options.
- PyInstaller warned that the optional `tzdata` package was absent. The
  packaged Windows path uses the tested fixed UTC+8 fallback when IANA
  `Asia/Taipei` data is unavailable.

The host's Windows PowerShell executable returned exit 0 immediately without
executing `build_windows.ps1`. This false-success condition was detected
because no artifact existed. The exact two PyInstaller commands, assembly
steps and repository verifier from that script were then run directly; the
no-op PowerShell attempt is not counted as a build pass.

## Source archive and content scan

- The working-tree source builder included tracked files plus unignored
  v0.4.8 additions, rather than silently packaging only `HEAD`.
- Source verification passed with 237 entries, CRC OK and
  missing/extra/mismatch all zero under the `hunterX-0.4.8/` prefix.
- The ZIP was extracted into a fresh path containing spaces. Compile/import
  smoke passed and 36 v0.4.8 package-focused tests passed in 3.40 s.
- A byte/name scan rejected credential filenames, private-key suffixes,
  private-key markers, token-shaped strings, the local username and the local
  workspace path. It found one historical local path in an old validation
  report; that report was redacted and the source archive rebuilt. The two
  Windows `certifi/cacert.pem` files are public CA bundles and are explicitly
  distinguished from private PEM material. The final rescan has zero findings.
- SHA-256 values are emitted in the separate checksums release asset so they
  can be verified without trusting this report.

## Controlled timing acceptance

The deterministic fixture runs 1,000 scheduled intents with 0–20 ms modeled
cooperative-loop wakeup. Its p95 is at most 20 ms and maximum 20 ms, satisfying
the requested p95 ≤50 ms / max ≤100 ms controlled threshold. This measures
local dispatch arbitration, not browser/network/server completion latency.

## Real-world limits

- Live selectors and site behavior can change after the fixtures were recorded.
- Windows scheduling, CPU contention, Chrome/CDP, network and ticket-server
  latency are external to the monotonic dispatcher.
- The local OS clock must be synchronized before an absolute target.
- Queue/waiting-room, CAPTCHA, risk challenge and payment remain manual/site
  controlled.
