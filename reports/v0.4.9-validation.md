The baseline suite had 710 passes and one stale version expectation. During the
change, legitimate failures were not hidden: a Windows 1 ms scheduling
assumption, new localhost-auth expectations, targeted-only coverage-floor
misapplication, pip-tools/pip incompatibility, a missing fake ready-state,
missing per-tab detail-refresh defaults and stale packaged UI versions were
diagnosed and corrected before their relevant suites were rerun. The originally
delivered ZIP also exposed a Windows Explorer incompatibility: synthetic `./`
members passed normalization but appeared empty in Explorer. The builder and
verifier were corrected, regression-tested, and the Windows asset was rebuilt.
The final artifact was additionally opened through `Shell.Application`, the
same compressed-folder namespace used by File Explorer, and returned 12 root
items instead of an empty view.

## Performance

The portable benchmark used 9 × 1,000 samples before/after, followed by a
15-sample confirmation and a same-host clean baseline checkout. Result
fingerprints were unchanged. Confirmed medians were generally within about 5%
of the clean baseline for the relevant refresh/classification paths; coordinator
idle, scheduled dispatch and 1,000-tab state tests showed no material regression.
Synchronous diagnostics measured approximately 0.82 ms/write and are already
rate-limited/bounded, so no second log queue was added.

## Limits and blockers

- No real inventory, order, CAPTCHA/queue bypass or payment was attempted.
- Live website DOM, account state, queue policy, inventory, network and browser
  latency cannot be certified by offline/synthetic tests or guaranteed.
- CodeQL and dependency review are configured and pinned in GitHub Actions but
  were not executed locally; local Ruff/mypy/Bandit/pip-audit gates passed.
- Persisted settings remain schema-compatible plaintext. A safe atomic DPAPI
  migration covering every profile/backup and non-Windows fallback was not
  proven; weak custom encryption was intentionally not introduced.
